# Auteur

**Model-agnostic product/UI motion graphics studio.**  
A brief becomes a typed `VideoPlan`, then deterministic HTML/GSAP, then an MP4 — with a visual QA and fix loop.

Auteur is built on one observation: Claude Opus 5.5 is not a video model. It writes code that a renderer turns into video. The quality comes from taste, constraints, and iteration — not from asking a model to one-shot a 60-second film. Auteur externalizes those constraints into templates and a critic loop, so a relay with ordinary models can produce work that looks art-directed.

> Status: v2. Local Studio, four scene layouts, Chinese typography, Windows voiceover, advisory VLM review, and per-scene incremental rendering. Four real films generated through an OpenAI-compatible relay, all at QA 100/100. Generated ambient score + SFX, normalized to −16 LUFS. Benchmark 01 is a public ToDopa concept study, not a blind Opus parity test.

### Studio

A local web workspace for briefs, model status, scene plans, video preview, QA, fixes, voiceover, and files.

```bash
pnpm run studio
# open http://127.0.0.1:5173
```

Production build:

```bash
pnpm run studio:build
pnpm run studio:serve
# open http://127.0.0.1:4310
```

![Auteur Studio](docs/studio-desktop.jpg)

The Studio is a local web app, not a Tauri shell yet. It binds to `127.0.0.1` and has no auth; do not expose it to a network.

Render mode: **Full** keeps fade/push transitions; **Scenes** caches each scene clip and re-renders only changed scenes, with hard cuts.

### Layouts

Four scene layouts share one design system:

- `device` — laptop/phone UI demo with camera and callouts.
- `data` — full-width chart/stat surface with an inline proof note.
- `type` — editorial statement with no UI chrome.
- `hook` — 9:16 opener with one oversized number and a note.

Try the fixture: `examples/plan-layouts.json` (device → data → type → hook).

### Chinese typography

`examples/plan-zh.json` renders Chinese copy and passes 100/100. The composition declares `lang="zh-CN"`, loosens tracking/line-height for CJK, and registers `Auteur CJK` via `local()` system fonts (Microsoft YaHei, PingFang SC, Noto Sans SC). It is deterministic on this Windows machine but does not embed a CJK font yet.

### What the real runs caught

- **Arc**: the model copied a scene headline into `brand.tagline`, so the same line appeared three times. Normalization now drops a tagline that repeats a headline.
- **Pulse**: paper-theme muted text failed WCAG at 4.21:1, and a scene without cards triggered a GSAP warning for `.ui-card`. The token contrast and the conditional animation setup were fixed in the template.
- **Orbit**: the 9:16 deck inherited `align-items: center`, which shrank the stage to the phone width and pushed the callout on top of the screen. The phone chrome title was also hidden behind the notch. Both are fixed; the callout now sits outside the device.

### Audio

A deterministic ambient bed and UI whooshes/ticks are generated with FFmpeg at render time. No third-party audio, no sample licensing. The mix targets −16 LUFS / −1.5 dBTP; `qa` measures integrated loudness and true peak. Levels live in [config/audio.json](config/audio.json).

Voiceover uses Windows SAPI locally (`voice.wav`), starts at 300 ms, and ducks the bed to 42%. The Studio has a voice textarea; the CLI writes the same files. macOS/Linux TTS is not implemented rather than faked.

## How it works

```
brief
  → director model (VideoPlan JSON)
  → template compiler (typed scene graph → HTML/CSS/GSAP)
  → HyperFrames render (headless Chrome + FFmpeg)
  → critic (DOM + media + HyperFrames + optional VLM)
  → deterministic fixes (JSON Patch)
  → re-render (content-hash cache)
```

The model never writes HTML or CSS. It fills a constrained `VideoPlan`: scenes, copy, UI blocks, callouts, camera keys, transitions. Layout, type scale, easing, safe areas, and motion are owned by the template. That is what makes a weaker model usable.

- FFmpeg and FFprobe on `PATH`

## Real generation with your relay

Auteur is OpenAI-compatible and multi-model. You can use different models for directing, fixing, and visual review.

```bash
cp .env.example .env.local
# Fill AUTEUR_RELAY_BASE_URL, AUTEUR_RELAY_API_KEY, and model names.
pnpm run doctor
pnpm run make -- --brief briefs/arc.md --out arc
```

`.env.local` is gitignored. Never commit it.

### Roles and fallbacks

`config/models.json` defines model entries. `config/roles.json` maps roles to fallback chains:

```json
{
  "director": { "chain": ["director-primary", "director-fallback"], "temperature": 0.35, "maxTokens": 8000 },
  "fixer":    { "chain": ["coder-primary"], "temperature": 0.2, "maxTokens": 6000 },
  "critic":   { "chain": ["vision-primary"], "temperature": 0.2, "maxTokens": 4000 }
}
```

`doctor` probes `/v1/models`, JSON output, and image input, and writes `config/capabilities.local.json`. If no vision model is available, visual review is skipped and the deterministic DOM/media checks still run.

## What the critic checks

- **DOM**: horizontal overflow, clipped text, callout/copy overlap, safe margins, minimum type sizes.
- **Media**: resolution, fps, duration, frame count, black frames, integrated loudness, true peak.
- **HyperFrames check**: runtime errors, layout occlusion, container overflow, WCAG contrast, motion.
- **Fixer**: converts actionable issues into JSON Patch operations, validates the patched plan, re-renders, and reports the score delta.

The local example passes 100/100. The score is a guardrail, not a substitute for human taste.

### VLM advisory review

If a vision model is available, `qa` and the Studio send a 2×2 contact sheet to it and ask for a short critique. VLM findings appear in the issue list and rubric (`VLM 72` in the Studio demo) but **do not** lower the scored verdict. In the Studio demo the scored QA is 100/100 while the VLM still flags five composition issues; one of those — repeated left-copy/right-panel frames — led to the `data` and `type` layouts.

### Scene mode and cache

`--scenes` renders each scene as its own clip, caches each clip by a scene/template/quality hash, concatenates the clips with FFmpeg, then mixes the global audio. Editing one scene re-renders only that clip. The tradeoff: scene mode uses hard cuts, not the fade/push transitions of full mode. Full mode stays the default.

```bash
pnpm run render -- --plan examples/plan-layouts.json --scenes --force
pnpm run render -- --plan examples/plan-layouts.json --scenes  # cached clips
```

[Watch the four-layout scene-mode demo](docs/media/layout-demo.mp4) · [QA report](docs/qa/layout-demo.md)

Every full render also hashes the plan, template version, audio config, and voice file. If the output and hash match, `render` returns immediately; `--force` bypasses it.

## Current limitations

- Four layouts on one base template, not four independent template files. Layouts share typography and motion.
- Chinese uses local system fonts (Microsoft YaHei/PingFang/Noto); a bundled CJK subset is not packaged yet.
- The Studio is a local web app, not a Tauri desktop shell. It has no auth and must stay on `127.0.0.1`.
- Voiceover is Windows SAPI only. Music and SFX are synthesized, not composed tracks; no beat-sync or lip-sync.
- VLM review is advisory and depends on a vision-capable relay model; it never changes the scored verdict.
- Scene mode caches clips and re-renders only changed scenes, but uses hard cuts; full mode keeps transitions. There is no timeline editor.
- Motion graphics only: UI, typography, charts, product surfaces. No photorealistic footage.
- The QA score can be gamed by a clean but boring composition. Human review is still required.

## Roadmap

1. Per-scene preview/render and selective re-render, replacing the whole-film cache.
2. Embedded CJK font subset and brand kit; then more independent templates.
3. Timeline/scene inspector in the Studio, plus keyboard shortcuts and project folders.
4. Controlled benchmarks: same prompt and duration when public prompts are available; Code2Video five-axis scoring; cost/time.
5. Integrations: OpenMontage, Remotion adapter, GitHub Action, `npx` distribution.
6. Tauri desktop shell, signed installers, and a cross-platform TTS path.

## Security

- Keys live only in `.env.local` / environment variables. They are never logged or written into compositions.
- Generated compositions make no network requests. GSAP and fonts are local files.
- The Studio API binds to `127.0.0.1`, has no auth, and executes only the typed pipeline. Do not expose it publicly.
- The slice does not execute model-written code; it only consumes typed JSON.
- `runs/` and local capability files are gitignored.
